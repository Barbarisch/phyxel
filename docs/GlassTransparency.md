# Transparent Materials (Glass) — current-state reference

**What this is:** the reference for how transparent voxels (glass) render, and how the engine meshes
the voxels around them. It describes the system **as shipped on `main`**. Read §9 before changing
anything here.

**History:** the full fix plan and execution log are preserved in git: the bisect, four
design-check passes, the OIT investigation, the face-culling plan (section 17 of that revision) and
every measurement. See **`git show f109fd64:docs/GlassTransparency.md`**. §11 summarises it.

**Related:** [`VoxelDamageVisualization.md`](VoxelDamageVisualization.md) (the crack field glass
shares), [`LightingPipeline.md`](LightingPipeline.md) (receiver matrix; rule R10),
[`docs/StructurePipelineGaps.md`](StructurePipelineGaps.md) (logged gaps, §10).

## 0. In one paragraph

A material is **transparent iff its `alpha < 0.99`** in `resources/materials.json`, decided in one
place: `Core::isTransparentMaterial(const MaterialDef*)` (`engine/include/core/MaterialRegistry.h`).
Today that is **Glass only** (`alpha: 0.02`). Transparent faces carry instance bit 1. The opaque
pass discards them, and a **weighted-blended order-independent transparency (WBOIT)** pass draws
them. Glass casts no shadow, shows damage as bright frosted cracks, and is still a physics solid.
The mesher draws **opaque faces behind glass** (a window's stone reveal is visible through the pane)
and culls glass against glass, so a thick pane does not stack layers. This holds identically across
chunk borders.

## 1. Rendering path

| stage | where | what |
|---|---|---|
| flag | `ChunkRenderManager` (cube, subcube and microcube paths) | instance `reserved` bit 1 = transparent, bits 2–9 = quantized alpha |
| opaque pass | `shaders/voxel.frag` | `if ((flags & 2u) != 0u) discard;` near the top of `main`. Transparency is decided by the material's bit, **never by texture alpha** |
| pass gating | `Chunk::recomputeRenderFlags` → `hasTransparentVoxel()`; `RenderCoordinator::renderTransparentGeometryOIT` | the OIT pass runs only if a visible chunk is flagged. The flag scans cubes **and** static subcubes/microcubes, and `Chunk::setLodFaces` refreshes it. A stale flag here makes glass invisible (pinned by `ChunkRenderFlagsTest`) |
| OIT draw | `RenderCoordinator::renderTransparentGeometryOIT` | **6 indices per instance, not 36.** Each instance is one face quad; the 36-index cube draw under cull-mode NONE composited every surface twice |
| OIT shader | `shaders/transparent_voxel.frag` | samples albedo through the **class-aware** atlas path (`phxSampleAlbedo`, `shaders/voxel_world.glsl`: binding 1 = 512 px class, binding 5 = 1024 px class); **no texture-alpha discard**; Blinn-Phong sun highlight (exponent 64, ×0.3); frosted cracks (§4); WBOIT weight |
| composite | `shaders/post_process.frag` | accum RGBA16F + reveal R8: `color = mix(accum.rgb / accum.a, sceneColor, reveal)`, where reveal = Π(1 − α) over the layers |

`shaders/voxel_world.glsl` is the **one** copy of the helpers the opaque and transparent paths
share (absolute world position, face UV, atlas class select, `crackStyle` lookup). Three drifted
copies of these (flags, crack seed, atlas class) were the cause of several glass bugs; don't
re-inline them.

## 2. Material, texture and the transmission target

- **`alpha: 0.02`**, calibrated by measurement to a transmission of **T ≈ 0.80** (the reviewer's
  target band 0.75–0.85; measured 0.804). T does **not** follow `(1 − a)²`; it fits
  `≈ 0.86 (1 − a)^3.4` (open, §10). Re-measure T after any alpha, texture or OIT change; never set
  alpha by formula.
- **Texture:** 1024 px **RGBA**, generated by `tools/gen_glass_texture.py`: tileable irregular
  smudges, peak alpha 53/255, base RGB ≈ (218, 236, 240). Six face PNGs under
  `resources/textures/source/glass_*.png`. The texture's alpha shapes the smudges only; it does not
  decide transparency.
- **Guard:** `TransparencyTextureGuardTest` asserts every listed cutout/transparent material's
  source PNGs **keep an alpha channel** with real coverage (channels == 4, ≥ 1% of pixels below
  250). An RGB regeneration is what once made glass opaque (§11).

## 3. Shadows

**Transparent materials cast no shadow** in any cascade (reviewer decision; `LightingPipeline.md`
rule R10). `shaders/shadow.vert` moves any instance with flag bit 1 outside the clip volume. Measured:
the sun under a glass roof reads R = 1.000 of the unshadowed control.

## 4. Cracks on glass

Damaged glass draws its cracks in `transparent_voxel.frag` with **the same `crackField` and the exact
world seed** the opaque pass uses. They render as bright frost (`0.92, 0.95, 0.97 × light`) that
raises local alpha toward 0.85 along the crack lines, plus a small whole-pane haze with damage.
Glass `crackStyle` = 0.75 (dense, fine). Measured: a cracked pane reads +30.8 brighter than the
clean pane, against a noise floor of 0.24. Model and stages: [`VoxelDamageVisualization.md`](VoxelDamageVisualization.md).

## 5. Face culling around transparent voxels

**The rule.** A face of voxel **A** pointing at neighbour cell **B** is hidden iff
`B is occupied AND (B is opaque OR A is transparent)`.

| A (face owner) | B (neighbour) | drawn? | why |
|---|---|---|---|
| opaque | empty | yes | |
| opaque | opaque | no | |
| **opaque** | **transparent** | **yes** | seen through B, e.g. a window's reveal |
| transparent | empty | yes | |
| transparent | transparent | no | a thick pane's interior faces; drawing them would stack OIT layers |
| transparent | opaque | no | the glass face lies on the stone's surface |

Two *different* transparent materials touching would hide each other's faces. Only Glass exists,
so this can't happen today; tinted glass would make it a question (§10).

**Where it is applied:**

| path | how |
|---|---|
| cubes, in-chunk | `faceHiddenByNeighbor` lambda in `ChunkRenderManager::rebuildCubeFaces`, using `m_cellTransparent` |
| subcubes / microcubes, per-face and merged | `ChunkRenderManager::fineFaceHidden(g, level, selfTransparent)`, backed by `subCellClass` / `microCellClass` and the companion sets `m_subTransparent` / `m_microTransparent` |
| **across a chunk border, cubes** | `NeighborLookupFunc` returns `NeighborOccupancy {Empty, Opaque, Transparent}`, supplied by `Chunk::renderOccupancyAt` (`ChunkManager::rebuildChunkFacesWithCrosschunkCulling`) |
| **across a chunk border, sub/micro** | `NeighborFineLookupFunc(worldMicro, level)`, supplied by `Chunk::renderOccupancyAtFine` with exactly the `subCellSolid`/`microCellSolid` precedence. Without it, a 1-micro pane straddling a border drew a doubled seam |
| billboarded leaves | a leaf behind glass counts as exposed and emits its foliage cards |
| chunk sealing | `ChunkManager::isChunkCapped` requires an **opaque** cap. A chunk capped by glass is meshed, not sealed |

**Deliberately NOT changed (glass stays solid):** physics and collision (`visibleSolidCubeAt` and its
callers), grass cover (`neighborSolid`: glass on a grass top still covers it, including across a
border), the skylight roof scan, and the occlusion graph (`computeVisibilityMask` already treats
alpha < 0.99 as see-through).

## 6. Keeping chunk borders correct

A face on a chunk border depends on the neighbour chunk's cell, so an edit on one side must re-mesh
the other. Two mechanisms make that route-independent. Every edit path (player place/break,
fill/clear jobs, `POST /api/world/fill`, damage breaks, template/structure stamps, placed-object
clear, settlement build, snapshot restore/undo, move/rotate region) is covered without per-route
code.

1. **Border-class signature ripple.** `Chunk` keeps one 64-bit signature per face over its border
   cells' render classes (`computeBorderSignature`: cubes on the layer plus every sub/microcube
   whose parent is on it; an order-independent sum of splitmix64 keys; classes, not materials, so
   stone → brick does not ripple). A face is pending iff the current signature ≠ the **delivered**
   one (what the neighbour was last meshed against). `ChunkManager::deliverBorderRipple` consumes it
   at the end of every managed rebuild and calls `markChunkForRemesh` on that neighbour. The first
   computation seeds both values, so a chunk's first build never ripples (no cascade on load).
   Comparing with *delivered*, not the previous rebuild, matters: `removeCube` re-meshes at once
   with the cell empty, so a same-class swap would otherwise ripple.
2. **Every null-lookup rebuild ends in a managed one.** A chunk records its owning `ChunkManager` on
   its first managed rebuild (`Chunk::m_owner`). Any later rebuild **without** a neighbour lookup
   (e.g. `addCubesBatch`, the `/api/world/fill` path) sets `m_managedRemeshRequested` and marks the
   chunk for re-mesh. `ChunkManager::updateChunk` honours that flag even when `needsUpdate` was
   cleared by an intervening `updateVulkanBuffer()`. This fixes the chunk's own over-drawn border
   faces and delivers its border changes. It cannot loop, because the managed rebuild always has a
   lookup.

Both use `markChunkForRemesh` (mesh-only; never DB-dirty). Measured cost of the signature: **0.55%**
of a rebuild on terrain, **3.92%** in the worst case, a border layer made entirely of subcubes
(budget 5%, `T16`).

## 7. API and debug

- **`GET /api/debug/chunk_faces?cx=&cy=&cz=[&x1=&y1=&z1=&x2=&y2=&z2=]`**: a chunk's faces as
  **covered unit faces at microcube resolution** (a cube face = 81), split opaque/transparent by
  direction, optionally boxed to a world-cube region. Merge-independent, because it uses the same
  decoder as the unit tests (`engine/include/graphics/FaceCoverage.h`). Echoes the chunk and its
  `rebuilds` counter.
- **Transparency is material data:** it comes from `alpha` in `materials.json`. Place `Glass` with
  any place/fill route. No API sets per-voxel transparency or tint.
- The `OIT` log channel at TRACE says whether the transparent pass was SUBMITTED or SKIPPED each
  frame.

## 9. Rules for changing this system

1. **Transparency is decided by `Core::isTransparentMaterial`, nowhere else.** Route any new
   render-side transparency test through it.
2. **Shader changes** (`voxel.frag`, `transparent_voxel.frag`, `shadow.vert`, `voxel_world.glsl`,
   `post_process.frag`): run `.\build_shaders.bat` and **commit the regenerated `.spv`**; keep
   `tools/shader_manifest.py --check` green; update `LightingPipeline.md` §0/§9 when a receiver's
   lighting changes. `lighting_doc_check` does **not** fingerprint `transparent_voxel.frag` or
   `shadow.vert`, so nothing reminds you.
3. **Never let texture alpha decide transparency**, and never regenerate a transparent or cutout
   texture without its alpha channel (the guard test will fail).
4. **Re-measure T** (`glass_transmission.py`) after any alpha, texture or OIT change, and get the
   reviewer's visual confirmation before calling a glass change done.
5. **Face culling:** `neighborSolid` (cover) and `faceHiddenByNeighbor`/`fineFaceHidden` (visibility)
   are different questions; don't merge them. Physics must keep treating glass as solid.
6. **Any new edit route** must end in a re-mesh of the edited chunk: a dirty or remesh mark, or a
   rebuild of a chunk the manager has already meshed. §6 then keeps the borders right.
7. **Changing how chunks mesh at borders:** extend `ChunkTransparentCullingTest` T8 (chunked =
   whole) and T9 (routes) first.

## 10. Known limits and open work

| item | state |
|---|---|
| **LOD chunks draw glass opaque** | `LodChunkMesh::emitFaces` writes `reserved = 0` and culls against any solid neighbour. Latent: distance-driven chunk LOD is default-OFF. Logged in `StructurePipelineGaps.md` (2026-09-24) |
| **Tinted / coloured glass** | not supported: the OIT shader ignores `vTint`, and no API sets per-voxel tint. Two different transparent materials touching would also need a rule decision (§5) |
| **T vs alpha model** | T ≈ 0.86 (1 − a)^3.4, not (1 − a)²; the ~14% extra loss is unexplained. Calibrated empirically in the meantime |
| **Smudge texture repeats every voxel** | visible as a regular dot grid on large panes |
| **Far-origin parity** | the far-from-origin L4 test was deferred; parity rests on the shared `phxWorldPosAbs` helper |
| **Intermittent crash** | one crash during `clear_region` over damaged glass; not reproduced in six attempts |
| **Five pre-existing Vulkan validation errors** | fire with or without OIT; logged in `StructurePipelineGaps.md` (2026-09-23) |

## 11. History, in brief

- The OIT pass opened with an unconditional `discard` from `7a36910f` onward, so glass was never
  blended. It looked transparent only through **cutout holes** in its 64×64 RGBA texture (61.7%
  cutout).
- `2ea8b8d9` regenerated the texture at 1024 px **RGB**, with no alpha, and glass became opaque.
  Found by a gated bisect.
- The fix (`e995caad`) re-enabled OIT properly. Along the way it fixed the OIT shader sampling the
  placeholder for every 1024 px material, removed the 36-index double composite, routed transparent
  faces out of the opaque pass, added frosted cracks and no-shadow, generated a new texture, and
  calibrated alpha 0.5 → 0.02.
- The face-culling work (commits `56915ab5`…`d96ca6ce`) made opaque faces behind glass visible and
  fixed three chunk-border bugs it exposed. **A pre-existing one:** fill/clear/damage/stamp routes
  never re-meshed the neighbour chunk, which left holes. **The seam:** sub/micro faces at borders
  assumed exposed, which doubled thin panes. **Found live:** `POST /api/world/fill` never
  requested a cross-chunk re-mesh at all.

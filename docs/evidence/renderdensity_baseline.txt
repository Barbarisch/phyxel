================================================================================
D0 VERDICT — the plan's top-lever hypothesis was WRONG; the wall is the shadow pass
================================================================================
The ~32 ms dense-scene frame is ~75% SHADOW PASS (24-26 ms), not the 377k-face main geometry pass
(4.7 ms). Both the RenderDensityPlan §2 "load-bearing hypothesis" (main-pass 3x overdraw amplifier)
and B0's framing (the 32ms is the "377k-face render cost") MIS-ATTRIBUTED the cost to the visible
chunk pass. Direct measurement moves the target to the shadow pass.

Why the shadow pass is so expensive (code, RenderCoordinator.cpp:960-1006): it re-renders chunks in
the fitted shadow sphere every frame, **distance-culled ONLY (no frustum, no occlusion cull)**, with
the same 36-index amplifier (12 tris/face). So it almost certainly draws FAR more chunks than the 20
the frustum-culled main pass draws — a geometry/primitive-bound pass. Not yet measured: the shadow
pass's own instance/chunk count (no pipeline-stats counter on it — the D1 first step).

The 36-index amplifier is still real and worth removing (D1), but its payoff is now expected in the
GEOMETRY-BOUND SHADOW PASS (12->2 tris/face = 6x fewer primitives), NOT in main-pass fill.

IMPLICATIONS FOR D1 (redirected by this measurement):
1. TOP LEVER = the shadow pass. First diagnose it (add a pipeline-stats/scope: how many chunks/
   instances does it draw vs the 20 visible?), then cut it: frustum + occlusion cull the shadow pass
   (currently distance-only), and/or lower shadow-map resolution / cascade / update-frequency.
2. The 6-index quad (old D1) now targets the shadow pass's primitive count primarily; measure its
   delta THERE.
3. Main-pass overdraw is NOT the bottleneck — deprioritise.

DIAGNOSIS VERDICT — two levers, ranked:
1. THE 6-INDEX QUAD (kill the 36-index amplifier) is the top lever for the shadow pass: it is
   depth-only and primitive/vertex-bound, so 12->2 triangles/face = 6x fewer primitives
   (2.78M -> ~464k) and ~6x fewer VS invocations (1.86M -> ~310k) hits the exact bottleneck. No
   visual change, no risk of dropping casters. Also trims the main + reflection passes.
2. LIGHT-VOLUME FRUSTUM CULL of the shadow pass (138 -> fewer chunks): complementary, but must cull
   against the LIGHT frustum, NOT the camera frustum — a chunk behind the camera can cast a shadow
   INTO view, so a naive camera-frustum cull would drop valid casters. More careful; do after (1).

VERDICT: the 6-index quad is CORRECT and a real, no-downside win for the MAIN pass (~1.6 ms) and any
vertex-bound path — worth keeping. But it does NOT fix the frame, because the SHADOW PASS is NOT

degenerate triangles (they were depth-rejected cheaply; the covered shadow-map texel area is the same).
The A/B measurement refuted the projection — as intended.

LIKELY REAL SHADOW LEVER (INFERENCE, not yet measured): the shadow map is 4096x4096 = 16.7M texels
(RenderCoordinator.cpp:87), fit over a large frustum. A depth pass filling 16.7M texels every frame is
the suspected wall. TEST (D1b): drop to 2048x2048 (4x fewer texels) — if the shadow pass falls ~4x,
it is resolution/fill-bound. Other levers: tighter frustum fit, cascaded shadow maps, update shadows
every N frames. NONE measured yet.

================================================================================
D1b — SHADOW-MAP RESOLUTION TEST (measured 2026-07-08): resolution is only a PARTIAL lever
================================================================================
Changed the shadow map 4096² → 2048² (4× fewer texels), same dense scene + camera. Then also toggled
the D1 quad ON at 2048². (36-index unless noted; ±20% run variance, 4 reads each.)

  config                         Shadow ms   StaticGeom   frame / fps
  4096² + 36-index (baseline)     ~28         4.7          ~38 ms / ~26 fps
  2048² + 36-index                ~19.5       4.7          ~32 ms / ~28 fps
  2048² + 6-index quad            ~20         3.1          ~26 ms / ~35 fps

FINDINGS:
- 4× fewer shadow texels cut the shadow pass only ~30% (28→20 ms), NOT ~4×. So the shadow pass is only
  PARTIALLY fill/resolution-bound (~30%); a ~19-20 ms floor remains.
- That floor is NOT primitives (the 6-index quad left the shadow pass unchanged at both resolutions)
  and NOT mostly texels. With 138 shadow draws vs the main pass's 20 draws at ~0.24 ms/draw, the
  floor is most consistent with DRAW-CALL / per-chunk-bind COUNT (138 chunks, distance-culled only) —
  i.e. the culling lever from D1a. NOT YET CONFIRMED (needs a cull-count A/B).
- Combined 2048² + quad reached ~35 fps / ~26 ms (vs ~26 fps / ~38 ms baseline) — a real ~35% win, but
  the 2048² half costs shadow quality and is the wrong lever.

DECISION: reverted 2048² → 4096² (modest gain, quality loss, wrong lever). The quad (D1) is kept
(committed 682eb4a; free, correct, ~34% off the main pass). NEXT = D1c: cull the shadow pass to the
light volume (138 → fewer chunks) and measure whether the ~20 ms floor is draw-call-bound. If yes,
tighter culling / cascade / fewer draws is the shadow fix — no quality loss.

================================================================================
SHADOW-PASS CHARACTERIZATION SUMMARY — three levers tested, ~27 ms wall persists
================================================================================
The dense-scene wall is the shadow pass ~26-28 ms (~75% of frame). Tested:
  - primitives (D1 6-index quad, 6× fewer): NO effect.
  - resolution (D1b 4096²→2048², 4× fewer texels): ~30% (28→20 ms).
  - draw count (D1c light-frustum cull, 138→131): NO effect (chunks are in-volume).
Decompose the 2048² datapoint (shadow = fixed + fill·texels): fixed ≈ 17 ms, fill ≈ 11 ms @ 4096².
The ~17 ms FIXED component is immune to primitives, resolution, and (achievable) cull — most
consistent with PER-DRAW GPU overhead across ~131 draws (each = vertex-buffer rebind + push constant
+ drawIndexed; ~0.13 ms/draw × 131 ≈ 17 ms), plus ~11 ms shadow-map depth-fill/clear.

REMAINING SHADOW FIXES (structural — none a quick toggle; scope next):
  1. BATCH the shadow chunk draws (merge into fewer draw calls / a shared instance buffer) → attacks
     the ~17 ms per-draw floor. Biggest suspected win; biggest change.
  2. UPDATE CADENCE — render the shadow map every N frames, reuse between (near-free ~2× amortized;
     needs static-ish sun + care on camera motion).
  3. SHORTER shadow distance / CASCADE — smaller fitted volume → fewer chunks + less fill (quality
     tradeoff or cascade complexity).

================================================================================
D1 CORRECTION (2026-07-09) — the all-passes quad BROKE SHADOWS; fixed to main-pass-only
================================================================================
The pre-merge scripted pixel-diff (grass/foliage OFF, day-night PAUSED to remove the sun-drift
confound; noise floor then = 0 exactly) REFUTED the earlier eyeballed "pixel-identical" claim: the
6-index quad applied to ALL passes changed ~1.1% of viewport pixels, concentrated on shadowed faces.

ROOT CAUSE: the chunk SHADOW pipeline front-culls (ShadowMap.cpp:429, VK_CULL_MODE_FRONT_BIT — it
renders BACK faces of closed casters, a peter-panning fix). The 36-index cube emits BOTH windings per
face so a back face always survives; the 6-index quad emits ONE (front) winding → front-culled → that
face casts NO shadow. So the quad silently broke shadows (the D1 "shadow pass unchanged ~28ms" was a
timing null that hid a correctness change — the pixel-diff caught it).

FIX: apply the 6-index quad to the MAIN OPAQUE pass ONLY (back-culled). Shadow + reflection + OIT +
mirror reverted to 36-index (both windings). Re-diff (sun frozen, grass/foliage off):
  noise floor OFF vs OFF        : max_delta 0, 0.0000% — deterministic
  main-pass quad ON vs OFF      : viewport 16 isolated pixels differ (>8), max 147, mean 0.0007,
                                  99.997% within 2/255 — scattered silhouette-EDGE aliasing (the
                                  quad's diagonal split differs by ≤1px at some cube edges), NO wrong
                                  faces, shadows intact. = the shipped fine-merge "perceptually
                                  lossless" bar. Verified by a diff-highlight image (16 specks at edges).
  win preserved: static_prims 451,512→75,252 (6×), Static Geometry pass 4.7→3.0 ms; shadow back to
  2,783,964 prims (36-index, shadows correct).

s_quadDraw now DEFAULT ON (main-pass-only, verified). D1c s_shadowFrustumCull DEFAULT OFF (no win).
LESSON: a timing-null ("no effect on the shadow pass") is NOT an output-null — always pixel-diff a
render change, with grass/foliage off AND the day-night cycle paused (both are noise sources).

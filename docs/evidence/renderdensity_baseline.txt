================================================================================
D0 VERDICT — the plan's top-lever hypothesis was WRONG; the wall is the shadow pass
================================================================================
The ~32 ms dense-scene frame is ~75% SHADOW PASS (24-26 ms), not the 377k-face main geometry pass
(4.7 ms). Both the RenderDensityPlan §2 "load-bearing hypothesis" (main-pass 3x overdraw amplifier)
and B0's framing (the 32ms is the "377k-face render cost") MIS-ATTRIBUTED the cost to the visible
chunk pass. Direct measurement moves the target to the shadow pass.

Why the shadow pass is so expensive (code, RenderCoordinator.cpp:960-1006): it re-renders chunks in
the fitted shadow sphere every frame, **distance-culled ONLY (no frustum, no occlusion cull)**, with
the same 36-index amplifier (12 tris/face). So it almost certainly draws FAR more chunks than the 20
the frustum-culled main pass draws — a geometry/primitive-bound pass. Not yet measured: the shadow
pass's own instance/chunk count (no pipeline-stats counter on it — the D1 first step).

The 36-index amplifier is still real and worth removing (D1), but its payoff is now expected in the
GEOMETRY-BOUND SHADOW PASS (12->2 tris/face = 6x fewer primitives), NOT in main-pass fill.

IMPLICATIONS FOR D1 (redirected by this measurement):
1. TOP LEVER = the shadow pass. First diagnose it (add a pipeline-stats/scope: how many chunks/
   instances does it draw vs the 20 visible?), then cut it: frustum + occlusion cull the shadow pass
   (currently distance-only), and/or lower shadow-map resolution / cascade / update-frequency.
2. The 6-index quad (old D1) now targets the shadow pass's primitive count primarily; measure its
   delta THERE.
3. Main-pass overdraw is NOT the bottleneck — deprioritise.

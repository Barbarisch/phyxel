F3.2b -- brushes and picking (VoxelFoundationPlan §9b, §1 "brush", §7 item 4). Written 2026-11-16, BEFORE any code.

What exists: region edits take an arbitrary voxel box or sphere (F2.16), and the store writes them voxel by voxel
through BlockStore::set and collapses afterwards (F3.2a: +1.6 ms at 4 m, set +0.74, collapse +0.24).
What the plan asks: place / break with brushes of 1, 2, 4 or 8 voxels per side (12.5 cm .. 1 m) on the voxel grid,
in voxel coordinates over the API; picking returns a voxel position (and the face hit), not a Chunk*.

Change:
1. Brush = an axis-aligned cube of s = 1, 2, 4 or 8 voxels whose corner is a multiple of s (the brush grid, like
   today's cube on the metre grid); brushCell(p, s) = floor(p / s) * s. Any other size is refused. API:
   {"edit":{"brush":{"at":[x,y,z],"size":s},"material":"Stone"|"air"}} (world voxel coordinates; "air" = break).
2. Whole-block writes: BlockStore::fillBlock(b, m) writes a block that the edit box covers entirely as ONE directory
   entry (frees its detailed slot) and returns how many voxels changed (0, 512 or the count of differing voxels);
   RegionEdit::apply uses it for every block fully inside a BOX edit (spheres stay per voxel). A size-8 brush is one
   block: no per-voxel set, nothing to collapse. Exact: the changed-voxel box may grow to the block (the incremental
   rebuild is exact for any box containing the changes).
3. Picking: RegionEdit::pick(origin, dir, maxVoxels) -- a voxel DDA (Amanatides-Woo) across the region's chunk
   stores, skipping uniform air blocks a block at a time; returns the first solid voxel (leaf voxels count: they are
   solid in the store), the face entered through (normal), the distance, and the brush cells to break (brushCell of
   the hit) and to place (brushCell of hit + normal). API {"pick":{"origin":[x,y,z] metres,"dir":[x,y,z],"max_m":m}}.

Red first (CPU):
- VoxFoundStorageLab.FillBlockEqualsVoxelWrites: random stores, 2,000 random fills: fillBlock == 512 set() calls +
  collapse (store equal to the dense reference, detailed count equal, returned count = voxels changed).
- VoxFoundMesher.BrushEditsAreExactAndAligned: the two-chunk RegionEdit; 200 brushes (all 4 sizes, place and break,
  across the chunk border): the store equals a dense reference after each, voxelsChanged exact, the incremental lists
  equal a full rebuild (faces / sprigs / connectivity) every 20 edits; size 3 / 0 / 16 refused.
- VoxFoundMesher.PickFindsTheFirstSolidVoxel: 400 random rays (incl. axis-aligned and through the chunk border, from
  inside air and from inside solid) on the two-chunk region: pick == a brute-force reference (the solid voxel whose
  box the ray enters first; slab test over every voxel in the ray's bounding box), same voxel, normal and distance
  (1e-4 voxel).
All red on stubs.

Predictions (live, gate region, Release, one session; the F3.1 / F3.2a gate's generator for the comparison, plus
brush edits at points picked by rays from the 5 poses' cameras):
1. Exact: 0 mismatches in every verified edit; 0 px vs replace_all.
2. Brush edits, request to lists ready (median): size 1 0.2-0.45 ms, size 2 0.25-0.5, size 4 0.3-0.55, size 8 (1 m)
   0.35-0.6 ms -- below F3.2a's unaligned 1 m (0.66) because the block write replaces 512 sets + the collapse.
3. The F3.1 generator's unaligned boxes: 4 m back to 5-7 ms (F3.2a 7.2; F3.1 6.2), 1 m 0.45-0.66.
4. Pick: 0.005-0.05 ms per ray up to 64 m (most of the path is uniform air blocks skipped 8 voxels at a time).
5. Pick hits from the 5 poses (rays through the screen centre): every hit's voxel is solid and the voxel before it
   along the ray is air (checked live by reading the store back through the pick's own path).

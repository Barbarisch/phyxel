FOUR BUGS FOUND, all the same family (a subsystem the EDITOR wires and the shipped
scaffold does not):
 1. VFX never ticked: RenderCoordinator::updateVfx is called ONLY in Application.cpp, so
    spells queued effects that never animated or drew ("why don't i see any spell effects").
 2. World overlays projected through the CAMERA-RELATIVE render view matrix (eye at the
    origin, for float precision at continental coordinates). Absolute world positions came
    out behind the camera: worldToScreen rejected 3/3 combatants (queued=0 projFail=3).
    This silently broke speech bubbles and the "[E] Interact" prompt in EVERY shipped game
    too. Fixed at the source: RenderCoordinator::getWorldViewMatrix() + a doc note on the
    cached one saying not to project through it.
 3. My own entity_damage test command called hc->takeDamage directly, bypassing the
    CombatSystem funnel that raises death events - enemies sat at 0 HP but "alive" to the
    director and the encounter never ended (wedged a whole probe run). Now routed through
    the funnel.
 4. UISystem::render early-out ignored nameplates_, so plates would vanish in any scene
    with no visible HUD screen.

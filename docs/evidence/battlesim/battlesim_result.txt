THREE RUNS, THREE DISTINCT FAILURES - each a real defect, not a flaky test:
 RUN 1 everyone died with ZERO combat log lines. The caster cast hook was never wired, so
   RangedCasterBehavior fell to its raw-takeDamage fallback: no CombatSystem, no death
   events, no VFX, no logs - combatants died of nothing. Also the 5th literal-format
   logger bug (CombatBehavior "{:.1f}") hid melee hits, and casts were logged at DEBUG
   (invisible in Release - a lesson already in my notes, repeated anyway). And the
   UNALIGNED observer was murdered by both armies: unaligned means hostile to everyone,
   so a spectator inside a 40u aggro radius is just a target.
 RUN 2 nothing happened AT ALL: aggro 26 with the lines 28u apart meant nobody could ever
   see anyone. (FPS 89 with 40 idle characters vs 32 mid-fight - the cost is combat.)
 RUN 3 (this one) passes. The generator now ASSERTS the geometry both ways:
   line gap < aggro < observer distance, so neither failure can recur silently.

ENGINE FIXES THIS INCREMENT: CombatBehavior::acquireTarget never checked m_faction despite
the header promising it (any group fight was a free-for-all); faction now lives on
Scene::Entity so combatants can read each OTHER's allegiance. NPCManager attaches the cast
hook at spawn so real-time spell damage always goes through the funnel.

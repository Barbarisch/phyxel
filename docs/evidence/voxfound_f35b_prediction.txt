F3.5b -- incremental connectivity (VoxelFoundationPlan F3.5a: owed before F3.5's second run). Written 2026-11-16,
BEFORE any engine code change.

Why: F3.5a's uncontended A/B (voxfound_f35a_ab.json) -- a full-block brush is 0.61-0.72 ms to lists ready and 0.35 ms
of it is connectivityFromBlocking's flood over the chunk's 32^3 blocks, run whenever a block's "blocks sight" bit
flips (every full-block place / break does).

Design (exact by construction): per chunk a component label per block (-1 = blocking), union-find over the labels, a
face mask per root (which of the 6 chunk faces the component touches), and a histogram of root masks (64 entries);
FaceConnect[f] = OR of every mask with count > 0 that has bit f (= the flood's out[f] |= faces per component).
- A block that OPENS: a new root, the distinct roots of its open neighbours unioned into it, mask = their OR | its own
  face bits. Never floods (adding a cell can only merge).
- A block that CLOSES: no open neighbour -> it was a component alone (its mask leaves the histogram). Else a local
  test in its 3x3x3 neighbourhood (clipped to the chunk): if every open 6-neighbour is reached from the first one
  through open cells of the neighbourhood other than it, the component stays connected; and if, for each chunk face
  the block touched, a reached cell touches it too, its mask is unchanged -> nothing else changes. Otherwise the
  chunk floods (a rebuild of every label) -- the only flood left.
- Several flips in one edit are applied one at a time (the not-yet-applied ones read with their old bit).
- {"legacy":true} (F3.1's A/B) keeps the flood on every edit; F3.5b's A/B: {"legacy_connect":true} floods whenever a
  bit flips (F3.5a's path).

Predictions:
1. Tests (red first on a stub that floods on every update): random flip sequences on 32^3-block grids (sparse /
   dense / mixed, single flips, whole-region boxes, cells on chunk faces and corners) -> connect() = the flood at every
   step; a brush-like sequence (single blocks in open air and on the ground) floods on < 5 % of its updates. The
   region test (RegionEdit) stays equal to a full rebuild. CPU and GPU suites green.
2. Live, uncontended, F3.5a's A/B script with {"legacy_connect":true} as A (same seeds, ABBA, every edit verified):
   connect_ms median 0.35 -> <= 0.02; request to lists ready median interior / face / edge / corner each <= 0.40 ms
   (F3.5a: 0.66 / 0.61 / 0.72 / 0.48 minus ~0.33); floods on <= 10 % of edits; 0 mismatches.
3. Memory: labels + parents ~0.25 MB per chunk, ~8 MB on the 32-chunk gate region (edit_store_bytes is unaffected;
   reported separately).
Stop line: any connectivity mismatch stops the run there.

F2.15 prediction (written 2026-11-14 before any code): §4.6 item 8, face direction culling.

Design: clusterFaces sorts each cluster's faces by (cell, direction), so a cell's six direction groups are contiguous
sub-ranges of it. Each Level keeps BOTH cluster lists over the same face buffer: per cell (F2.11) and per (cell,
direction). The cull pass (voxfound_cull.comp) gets a direction test per command: a group of +axis faces lies on
planes in [lo, hi] of the axis, so it can face the camera only if cam > lo (minus a 1 cm margin); a -axis group only
if cam < hi. CPU reference VoxFound::faceGroupMayFaceCamera. Runtime: {"dir_clusters":bool} uploads the per-direction
list, {"dir_cull":bool} turns the test on (main view, multidraw path; shadows and the direct path unchanged).

1. Unit (red first): for random faces in random boxes and random cameras, no face that faces the camera (dot(normal,
   cam - point on face) > 0) is in a group the test rejects; and for a camera outside a box, the groups on its far
   side ARE rejected. Red on a stub (rejects none / rejects all).
2. Pixels: per-direction clusters with the test on vs off: 0 px (only back faces go); per-cell vs per-direction
   clusters, test off: 0 px (same faces, same order within a level and chunk).
3. Commands: per-direction clusters x4-5.5 the per-cell count (not every cell has all six directions). Faces passed
   to the vertex stage with the test on: 45-60 % of the visible clusters' faces (about half face away; groups that
   straddle the camera plane stay).
4. Whole frame (P harness, 8 pairs x 5 poses, LOD off = the default), A = per-cell, C = per-direction + test:
   ground poses -0.2..-0.8 ms (the face scope was 3-5 ms there; F2.9's frustum culling of 20-33 % of faces saved
   7-14 % of it, so dropping ~half saves ~15-25 % of it, minus the command overhead); from above +-0.2 ms. B (per-
   direction, no test) vs A: the command overhead alone, 0..+0.3 ms (F2.11: 2-block clusters, a similar command
   count, cost 0..+0.26).

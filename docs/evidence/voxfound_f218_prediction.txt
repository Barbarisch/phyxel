F2.18 -- the plan's F2 list after item 10: T-junction cracks at merge borders (RenderOptimization.md:489;
VoxelFoundationPlan §4.6 note: "Cross-block merging creates more T-junctions, so F2 has to handle it, not inherit it").
Written 2026-11-15, BEFORE any code.

Measured first (no code changed; tj probe, scratchpad tj_probe.py):
- Metric: debug view 11 (/api/debug/shadow {"mode":11}: every voxel.frag fragment is a flat 0.5 grey before shading),
  the 3D viewport minus the editor overlays (x 425-1195, y 105-620 of the 1600 x 900 frame); a CRACK pixel differs
  from the dominant flat value by > 25 while both its left+right or both its up+down neighbours are flat (<= 6).
- Scene: engine-generated /api/debug/voxfound_preview Perlin s7 region 254..257 x 0..1 x 2..5, editable, sprigs off,
  world hidden, LOD off. With flora the canopy and small flora parts are ~1 px dots of another colour (not
  cracks), so the crack metric runs on the SAME region with flora off (bare terrain, 83,636 faces).
- Today, bare terrain: overview_south 185, top_down 190, forest_floor_open 69, east_low 1, canopy_close 87 crack px.
  Single pixels, scattered, not on the 32 m chunk lines; visible as grey dots on the white ground in the captures.
  They show even straight down (top_down), unlike the old renderer's note.

Cause (hypothesis): (a) T-junctions: the run merge emits neighbouring coplanar quads with different extents, so a
corner lies mid-edge of the neighbour; after projection + sub-pixel snapping the corner is not exactly on that edge
and a pixel centre can fall in the sliver. (b) chunk seams: voxfound_face(_mdi).vert computes
(origin - camInt) + camFrac FIRST and adds the local position after, so a world point shared by two chunks rounds
differently on each side.

Design (one knob, {"tjunction": 0|1|2, "tj_px": f}, the voxfound preview; the 4 free push-constant bytes at offset 28):
0 = today. 1 = exact sums only: (origin - camInt) + local is exact in float (multiples of 1/8 m, small), camFrac
added last, so a shared world point is bit-identical in both chunks. 2 = exact sums + each quad grown in its own
plane by a SCREEN-sized margin: per corner, outward along u and v by t = f px / (the screen-space speed of that axis
perpendicular to the edge), clamped to 1/16 m (half a voxel), none behind the camera. The texture is a function of
the (grown) position, so overlapping coplanar neighbours shade identically; only silhouettes can move, by <= f px.
Default f = 1/16 px (the sliver is ~1/256 px: snapping at 8 sub-pixel bits).
Shadow casters (voxfound_face_shadow.vert) are NOT in this step; whether the shadow map leaks too is measured and
recorded, not fixed here.

Red first: the knob is plumbed with a stub (levels 1/2 change nothing): the crack counts at level 2 = level 0 = the
numbers above (red). Then the shader.

Predictions (bare terrain crack px; flora scene for pixels and cost):
1. Level 1 (exact sums): removes only the chunk-seam share. >= 70 % of today's crack px remain (most dots are off
   the chunk lines).
2. Level 2 (f = 1/16 px): crack px <= 5 % of today at each pose (sum of the 5 poses 532 -> <= 27), 0 at >= 3 poses.
3. Pixels, flora scene, shaded (mode 0), level 2 vs 0 at forest_floor_open and overview_south: differs only at the
   dots and silhouettes, <= 0.1 % of the viewport's pixels; control (0 vs 0) 0 px.
4. Whole frame, 8 pairs x 5 poses, level 2 vs 0 (flora scene): +0.0..+0.15 ms (two more matrix-vector products and a
   few divides per vertex in the main view; shadows untouched). Measured only on a free GPU.
Stop line: if level 2 does not bring the dots to <= 5 %, the cause is not (a)+(b): diagnose, do not raise f blindly.

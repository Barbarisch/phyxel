Today (F2.15): every cluster (one cell's direction group) owns a fixed indirect command; the cull pass writes
instanceCount 0 for a culled one, and ONE vkCmdDrawIndexedIndirect walks all of them: 10,889 commands on the gate
region vs 2,385 per cell. The extra commands alone cost +0.09 / +0.07 / +0.68 / +0.10 / +0.26 ms (overview, top_down,
forest_floor_open, east_low, canopy_close), which eats the whole direction-culling gain at forest_floor_open.

Change:
1. Compaction: the cull pass appends only the visible clusters (atomic counter per multidraw: solid, leaf mass) and
   the draw becomes vkCmdDrawIndexedIndirectCount (Vulkan 1.2 core; the drawIndirectCount feature gets enabled at
   device creation). Each command's chunk origin (read through gl_DrawIDARB) is written next to it into a per-frame-slot
   origin table; RenderPipeline keeps a small cache of set-1 descriptor sets keyed by (table, origins) so the per-slot
   tables are not rebound per frame (a rebind waits for the device).
2. Run merging: consecutive visible clusters of the same chunk, level and multidraw whose faces are contiguous in the
   face buffer become ONE command (a thread is a run head unless its predecessor is visible and mergeable; heads scan
   forward at most to the next multiple of 32 clusters, so the work per thread is bounded).
3. Direction order within a cell: -x, -y, -z, +x, +y, +z (was -x, +x, -y, +y, -z, +z). A camera outside a cell's box
   sees one side per axis; in the old order those groups are never adjacent (runs per cell 3 - 2/4 = 2.5 expected over
   the 8 octants), in the new one 4 of the 8 octants are a single window (expected 1.75). The face order changes, the
   face set does not. Build knob {"dir_order":"axis"} keeps the old order for the count comparison.
Knob: {"mdi_compact":bool} at runtime, the A/B switch.

Red test first: GPU, random clusters (chunks, levels, solid/leaf split, contiguous and broken face ranges), random
frusta and cameras: the multiset of (face index, origin) the compacted commands draw = the one the per-cluster
commands draw, and the command list = the CPU reference (mergeVisibleRuns) as a set; red on a stub that writes no
compacted commands.

F3.2a -- the edit store becomes the BlockStore (VoxelFoundationPlan §9b). Written 2026-11-16, BEFORE any code.

Today (F2.16-F3.1) RegionEdit keeps each chunk's voxels as a dense VoxelGrid: 256^3 B = 16.7 MB per chunk, 545.5 MB
(edit_store_bytes) for the gate region's 32 chunks. F1 built the store's CPU form (BlockStore: 8 B directory entry per
8^3 block, detailed blocks 512 B material + 64 B mask in a pool, collapse() per edit batch) and measured it on the same
forest (Perlin s7 forest (8160,96): 3.90 MB per 32 x 32 m footprint with flora, 6.04 detailed blocks per column).

Change:
1. RegionEdit::Chunk holds a BlockStore (built from the region build's grid once per chunk; collapse() at the end of
   every edit that touched the chunk). The dense grid is dropped after the conversion.
2. The incremental rebuild reads the store: meshRunsPlan (and the legacy whole-row executor), foliageSprigsBox /
   updateSprigs, blockBlocking / updateBlockBlocking get BlockStore overloads (the same code, templated on the reader).
3. Paths that need a dense grid get one built on demand from the store (BlockStore -> VoxelGrid): verify, replace_all,
   the opt-in device rows (whole upload on a resident miss). Their cost is reported, not part of the edit path.

Red first:
- CPU VoxFoundMesher.BlockStoreReadersEqualTheDenseOnes: engine terrain + random brush churn; after every edit the
  BlockStore overloads (rows delta, sprigs, blocking) equal the VoxelGrid ones on the same voxels, and the store
  equals the dense reference (compareToReference). Red on stubs that return empty results.
- CPU VoxFoundMesher.RegionEditAssemblesOnlyWhatChanged keeps passing with the store inside RegionEdit; plus
  RegionEdit::bytes() <= 1/5 of the dense bytes on its two chunks.

Predictions (live, gate region, Release, F3.1's gate script and edit generator, every edit verified):
1. Exact: 0 face / sprig / connectivity mismatches; 0 px vs replace_all at the two poses.
2. Edit store: 40-80 MB for the 32 chunks (16 forest footprints x ~3.9 MB, the upper chunks almost all one entry per
   block + their 256 KB directories) vs 545.5 MB: 7-14x smaller (F1's gate asked >= 5x).
3. Edit cost (request to lists ready, median): 1 voxel 0.3-0.5 ms, 1 m 0.5-0.67 ms (F3.1 0.53; reads through the
   directory cost more per cell, collapse adds 0.02-0.1 ms), 4 m 6-10 ms. Stop line: 1 m median > 0.67 ms -> profile
   before anything else (the F3.1 gate must keep holding).
4. Region build + conversion: +0.3-1.5 s on the ~26 s build (32 x 16.7 M voxels scanned once).
